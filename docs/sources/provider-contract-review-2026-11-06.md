# Provider contract review: November 6, 2026

The scheduled provider contract monitor failed on November 5 and November 6 and holds open issues #126, #131, #132, #133 and the digest #103; the exact-ref release gate on tag `v0.9.16` failed for the same reason. All fifteen registered pages were fetched and reviewed before the fingerprints were refreshed. The baselines are the copies fetched for the November 4 review, each of which hashes exactly to the content pinned that day, so the differences below are exact and not inferred. The review also adds four pages to the registry, which now holds nineteen.

Only one claim the estimator depends on moved: the end date of GPT-5.6 Sol's promotional pricing. No published rate changed today, and no connector behavior changes in this review.

## Changes supported by the review

- [GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol) (#126). The promotion now has a firm end. Before: "GPT-5.6 Sol's promotional pricing is available at least through November 21, 2026." Now: "GPT-5.6 Sol's promotional pricing is available until November 30, 2026." The [pricing page](https://developers.openai.com/api/docs/pricing) carries the same sentence. Today's rates are unchanged and match the estimator: $4 input, $0.40 cached input and $20 output per million tokens, and $8, $0.80 and $30 for prompts over 272K tokens. Neither page names the rate that follows. An archived copy of the model page from August 19, 2026, before the promotion, lists $5 input, $0.50 cached input and $30 output, and the page still describes the promotion as a 20% input and 33% output reduction, which gives the same figures. The registry records this and pins the sentence; the estimator change is a separate pull request.
- [Claude Enterprise Analytics](https://platform.claude.com/docs/en/manage-claude/analytics-api) (#133). Before: "When `ending_at` is omitted (the default is the current time), the response includes a tail of data after `data_refreshed_at` that is incomplete." Now: "If you omit `ending_at`, it defaults to 31 days after `starting_at` or the current time, whichever is earlier. That range can run past `data_refreshed_at`, and data after that time is incomplete." Before: "Organizations without usage of that product see all-zero values rather than null." Now: "... see zero counts rather than a null object", followed by a new statement that individual fields inside these objects can be null, which means the value is not available, for example `distinct_skills_used_count` in `chat_metrics` when user activity is filtered by project. The other edits are wording only. Enterprise remains contract-only and untested, and no connector reads these endpoints. The registry records the default and the null rule, and pins them.
